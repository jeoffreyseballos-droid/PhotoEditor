# Phase 5 — local AI culling

PhotoAnalysis describes the source; CullingAssessment recommends a rating; user selection chooses what to edit. Built-in preset selection is a separate local workflow that resolves validated EditRecipes; it never changes culling evidence or originals. Phase 5 never trains a model or contacts a cloud service.

## Contract and persistence

Rust `photo_contracts::culling` is authoritative. `CULLING_SCHEMA_VERSION = 2` is independent of analysis/recipe/app/SQLite versions. Version 1 immutable snapshots remain on disk and are explicitly upgraded on read: old visual groups become conservative `similar`, with no claimed exact identity or completed membership. Their engine/cache version makes them stale until re-culling. `Stars` accepts only 1–5; `Option<Stars>::None` means not rated, never zero. Strict bounded deserialization rejects unknown/future/missing envelopes, bad source bindings, non-finite numbers, invalid confidence/geometry/group data and oversized payloads (128 KiB; at most 64 faces and 512 reasons). The shared v2 structured fixture is parsed and roundtripped by Rust contract tests; legacy loading is tested through the actual parser.

An immutable assessment records ID/time/type, AI stars, absolute/final scores, confidence, structured reasons (code, severity, confidence, subject index, optional measurement/reference), all measured features, source analysis ID/fingerprint, engine/model versions and cache key. `CullingState` composes the snapshot with independently persisted user rating, effective rating, selected flag, stale flag and user-state update time. There is deliberately no mutable user rating inside the immutable AI evidence.

Migration **007_culling.sql** adds:

- `culling_assessments`: append-only AI snapshots including compact feature and similarity payloads; old reasons remain intact.
- `culling_current`: current assessment pointer per job/asset/photo type.
- `culling_user_state`: nullable manual stars and independent editing-selection flag per job/asset, shared across photo types.
- `culling_rating_events`: append-only changes/clears referencing the AI snapshot visible when the override was submitted, suitable for future feedback research. No learning is implemented.
- `culling_runs`: latest job progress and photo type; startup marks queued/running work interrupted.

Migration **008_duplicate_content.sql** adds only a reusable per-job/asset full-file hash cache, with algorithm, OS file-generation stamp, SHA-256, byte length and update time. Relationships stay inside the existing immutable assessment JSON, not a redundant group database. `SimilarityContext` retains visual group ID/size/preferred IDs/relative gap/confidence/bracket flag and adds visual `kind` plus similarity score and an optional nested `ExactDuplicateRelationship` (group ID, size, canonical asset ID, content identity). The nested form allows an exact-copy family to also participate in a burst. Assessment-level `duplicate_content`, `duplicate_stamp`, and `membership_key` bind content, source generation and completed job membership. Related asset IDs are recovered from matching group IDs in the bounded job overview.

**Effective = user override, otherwise current AI rating.** Stale AI is excluded from effective ratings/filter counts, but remains inspectable as historical evidence. Manual stars and selection survive stale AI. Re-culling replaces only the AI pointer; clearing an override reveals the current AI rating. History is not pruned automatically and will need a future retention policy.

## Features and providers

`culling/features.rs` reuses the Phase 4 analysis and the renderer's shared, oriented, unedited linear-sRGB proxy (maximum edge 1600; reduced RAW path). No recipe values enter extraction. Common clipping/brightness/detail/noise, candidate level, subject geometry and subject/background EV are reused. Additional work supplies:

- Local face detections, source-normalized boxes, confidence and relevant-size gating.
- Fixed 64×64 face-region contrast-normalized Laplacian RMS, luminance and clipping. Proxy face widths/heights below 32 pixels are uncertain; 32–63 px detail has weak confidence; ≥64 px is eligible for relative comparisons.
- Softest reliable relevant face, max–min spread and indices below 45% of group median (median above 0.05).
- Visible box fraction and minimum distance to the source edge. These describe geometry, not whether the photographer intended a crop. They are not anatomical head/hair/chin or whole-body cutoff detection.
- Global directional gradient imbalance: a weak review signal, **not** a motion-vs-defocus classifier.
- Cell-averaged 64-bit difference hash, 8×8 linear luminance and 4×4 RGB color descriptor, aspect, timestamp and camera metadata. No filenames enter similarity decisions.

`FaceDetector` and `EyeStateDetector` are replaceable interfaces. Default face provider: local CPU **YuNet 2023mar**, fixed 640×640 BGR detector input with right/bottom padding; isolated `photo-face-helper` using the already bundled ONNX Runtime **1.29.0**. Confidence threshold 0.9, NMS IoU 0.3, at most 64 boxes. The provider verifies the pinned model SHA-256 before inference. Temporary BGR input/detection JSON are held under cache scratch and removed on normal completion/failure/cancellation; no crops, identities, embeddings or tensors are stored in the job database. Native hard crashes can leave scratch files, as with existing helpers.

Model: [OpenCV Zoo YuNet](https://github.com/opencv/opencv_zoo/tree/main/models/face_detection_yunet), MIT license. Immutable revision `f12e12798e8314f7c074a6656816c048dcc95b7a`; SHA-256 `8f2383e4dd3cfbb4553ea8718107fc0423210dc964f9f4280604804ed2552fa4` (232,589 bytes). `scripts/prepare-culling.mjs` downloads/verifies model and license during explicit native preparation, copies the helper, and bundles resources via the existing toolkit resource mapping. No runtime download. See [MODEL-NOTICES.md](MODEL-NOTICES.md).

**Actual eye-state inference is not implemented.** YuNet's face/landmark outputs do not establish eyelid state; a trustworthy licensed eye-state provider was not added. The default returns unavailable for each face (tiny faces uncertain). Available/open/closed/uncertain/not-visible are supported by the typed interface and structured tests, not claims about the shipping model. Uncertain, unavailable, profiles and missing evidence never become “closed” or “open.” Exceptional measured face focus, or strong focus plus Near/Burst leadership, can reach 5★ while retaining the explicit unknown-eye review reason; this is a technical recommendation, not an expression certification. User 5★ overrides remain available.

Missing or failed face providers remain distinguishable from a successful empty detection. Optional provider failures retain common measurements and a conservative rating. Undecodable/missing sources receive no image-quality rating; batch progress reports source-analysis failures and other photos continue. Exception: identical, readable but undecodable bytes still establish an exact relationship. The canonical stays not rated; a redundant copy receives 1★ explicitly for duplication, never for a fabricated quality defect. Hash failures are separately reported and cannot prove exact identity or uniqueness.

## Scoring policy v2

`score.rs` is the single versioned policy; feature extraction, storage and UI contain no star thresholds. Internal scores are 0–100; UI shows stars and explanations, not an over-precise quality score. Evidence confidence is heuristic strength/repeatability, **not a calibrated probability**.

| Score     | Stars | Meaning                                  |
| --------- | ----- | ---------------------------------------- |
| below 20  | 1     | Strong reject suggestion, never deletion |
| 20–39.999 | 2     | Significant issue / likely reject        |
| 40–64.999 | 3     | Usable / review useful                   |
| 65–87.999 | 4     | Very good / candidate for editing        |
| 88–100    | 5     | Excellent / strongest candidate          |

Base score 82. Portraits: reliable eyes-closed penalty 32 (+4/additional blink, capped at +8); reliably soft multi-person outlier 24 (+3/additional, capped +6); face boundary penalty capped at 6 across the whole image; extreme local clipping capped at 10 across the image. Face detail uses the existing contrast-normalized local measurement. A relevant face covering at least **0.008** of the frame, with detection confidence ≥0.85, detail confidence ≥0.7 and detail below **0.20**, triggers the centralized severe-focus gate. It emits `severe_subject_softness` and caps absolute/final score at 19 (**1★**) even if the frame is group-preferred. The scale condition protects small/distant and naturally low-texture detections from a confident unusable claim. Reliable strong face focus begins at **0.18**, but the severe gate takes precedence when its stricter relevance, scale and confidence conditions are met; exceptional focus begins at **0.45**. Fully evidenced open-eye/sharp-face portraits add 10. With eyes unavailable, strong focus adds 3 and exceptional focus adds 6 while the unknown-eye reason remains. A strong preferred Near/Burst leader or exceptional standalone frame can therefore reach 5★ without fabricating eye evidence. One blink plus meaningful framing/clipping defects can reach 2★, while ordinary blink/quality issues can occupy 3★.

Real estate ignores portrait eye/face rules: low global detail review penalty 8, level review 3, clipping weight 14. Landscape is more tolerant: detail 4, level 2, clipping 10. Non-portraits with strong detail, low estimated noise and very little clipping add 7. Neither type detects flash misfires, reflections, accidental occlusion or focus intent semantically.

Ordinary clipping >20% has a small capped 8-point review penalty. Bright/dark median alone warns without a penalty. Almost entirely clipped (>99.5%) and flat (tonal range <0.003) images cap at score 30; this can still mistake an intentional near-blank frame. Noise and directional detail are review-only. Low overall confidence (<0.7) floors the final score at 45 (3★); strong per-person blink/outlier evidence can independently restore confidence. Subject-background EV remains exposed evidence, not an automatic backlight penalty.

## Exact duplicates and visual relationships

Exact means equal **complete-file SHA-256 and byte length** (`full-file-sha256-v1`), including RAW/container metadata, not equal thumbnails or decoded pixels. Different filenames/folders can match; equal filenames do not prove anything. The inherited source fingerprint includes canonical path, size, mtime and ingested metadata, so it remains a source/provenance cache key, not duplicate identity. Files with identical pixels but different embedded metadata or encoding are not exact copies. SHA-256 collision resistance is assumed; this is not an adversarial forensic verifier.

Exact content buckets cover the entire job independently of the visual window. Sort each bucket's stable asset IDs; the smallest is canonical. Group ID hashes algorithm, digest, length and sorted member IDs. This is deterministic for the same catalog membership; adding a lower-ID copy can change the canonical, and a newly ingested job has new IDs. No filenames or user stars determine it. All copies persist and remain selectable. The canonical keeps its normally assessed quality rating; redundant copies get final score 5 / **AI 1★**, confidence 1 for byte redundancy. Their absolute quality evidence is retained. This exact-only rule overrides the ordinary low-confidence rating floor and adds `exact_duplicate`; the canonical gets `preferred_copy`. A user 5★ override still yields effective 5★ and never removes the relationship.

`similarity.rs`, version `content-visual-time-anchor-v2`, extends the existing descriptor comparison. Exact families collapse to their canonical for visual ranking, then expand into comparison context, so copies cannot all become preferred visual frames. Every visual pair must have aspect within 3%, non-flat luminance contrast ≥0.008, dHash Hamming distance ≤14, centered 8×8 luminance mean error ≤0.075 and 4×4 RGB mean error ≤0.20:

- **Burst / sequence**: additionally same known camera, known capture times within 8 seconds, Hamming ≤10 and luminance error ≤0.055. Filenames are never sequence evidence.
- **Near duplicate**: otherwise Hamming ≤3, luminance error ≤0.02, color error ≤0.04, with time unknown or within 8 seconds and no known camera disagreement. Tiny visual changes can qualify without matching file bytes. Expressions are not modeled.
- **Similar composition**: passes the broader visual gate but lacks the stricter near/burst evidence (e.g. a later moment or different camera). This explicitly conservative category receives **no relative rating adjustment**.
- **Unique image**: complete hash and feature measurement, but no exact/visual relationship found in the current bounded search. This is not a global perceptual uniqueness guarantee. Incomplete/cancelled/failed/stale evidence is unclassified instead.

Assets are ordered by capture timestamp then stable ID. Compare at most 64 recent anchors; each visual group has at most 32 distinct-content representatives (expanded copies may increase displayed image count). Every representative must match the anchor, avoiding unlimited transitive chains. The weakest match determines group category: any similar-only pair makes the group Similar Composition, all burst pairs yield Burst, otherwise Near Duplicate. Far-apart or visually changed moments therefore cannot receive aggressive duplicate penalties. This search can miss nonadjacent near matches or split a long series; **exact buckets have no such window limit**. EXIF time is naive local time unless an explicit offset is present; camera identity/time metadata can be missing or inaccurate.

Best **ungated technical ranking score**, independent of manual stars, determines visual preferred candidates; retain ties within one point. The lightweight overview chooses one deterministic lowest-relative-gap representative (then filename/path/ID) for photographer-facing BEST and Duplicate Hide behavior, while the immutable assessment keeps every technical tie for inspector review. Severe-defect caps are then applied to the absolute and final rating, so a five-frame blurry group may still have a relative winner while every member remains 1★. Near/burst preferred +3 / alternative −3 is modest relative ranking and cannot override a severe gate. Similar composition keeps technical reference frames/reasons but no bonus/penalty. `group_focus_reference` records the selected frame's reliable face detail and the visual group's median for inspector diagnostics. Reasons also include `near_duplicate`, `burst_sequence`, `burst_alternative`, `similar_composition`, `preferred_candidate` and `similar_alternative`, with preferred filenames resolved from IDs in the inspector. Burst luminance spread >0.12 gives a possible-bracket warning, not HDR eligibility or automatic discard. The scorer is `photo-culling-real-photo-calibration-v3`; this revision calibrates existing evidence but adds no eye inference or new model.

## Cache, rerun and cancellation

Full files stream through a 1 MiB SHA-256 buffer on first cull or changed generation. Cancellation checks each chunk. Cache validation uses an opened regular file: Windows volume/file ID, creation/last-write/**change time** and length; Unix device/inode, size, mtime and ctime including nanoseconds. The stamp is not duplicate identity. Windows handles deny concurrent write/delete sharing during hashing; handle/path stamps are checked before/after reading, and generations are rechecked after feature extraction and before publication. Missing/untrustworthy filesystem generation information fails the identity check conservatively; no unsafe size/mtime-only fallback. Restoring size and modification time after an ordinary byte edit does not preserve the tested Windows change token. Network/unusual filesystems and privileged timestamp tampering are not certified. See [Windows FILE_BASIC_INFO](https://learn.microsoft.com/en-us/windows/win32/api/winbase/ns-winbase-file_basic_info) and [Unix MetadataExt](https://doc.rust-lang.org/std/os/unix/fs/trait.MetadataExt.html).

Feature identity includes source fingerprint, PhotoAnalysis ID/schema, photo type, culling schema/engine, face/eye identities, feature extractor and similarity versions. Final identity adds structured relationships, full-content identity, generation and a digest of sorted job asset IDs. Recipes, exposure/HSL/local-mask edits, user stars and editing selections are absent. First binding of legacy/unbound analysis, or changed full content, invalidates Phase 4 source analysis before reuse; this closes its inherited same-size/same-mtime blind spot **for culling**. Other render/ingestion caches retain their existing behavior. Failed measurement is never treated as a successful content-to-analysis binding.

Reads validate current source generation without rehashing full RAWs. Changed/missing/stale members invalidate both exact and visual connected relationships, including overlaps. New catalog membership marks prior completed groups stale; Run / resume hashes the new/changed files, reuses unchanged feature measurements and recomputes job-wide relationships. New exact and near D images join A/B/C without changing user intent. Originals removed from disk remain catalogued under the established ingestion policy and become unclassified/unavailable, not silently deleted.

`Run / resume` uses cached hashes when generation matches (zero full-content bytes reread), reuses valid bound analysis/features, then regroups/re-scores. `Re-cull all` deliberately rehashes and re-extracts culling features; unchanged full content still reuses bound Phase 4 analysis. First-time upgraded/binding work can refresh analysis once. The source-analysis inspector can explicitly invalidate analysis/segmentation. Same-version failed detectors can be retried with Re-cull all. Model preparation/constants remain the supported update path.

One culling batch at a time; at most **5,000 assets/job**, additionally limited by a 64 MiB serialized feature/evidence budget (not a heap-memory guarantee). The grid renders 60 cards/page and each relationship inspector 24 thumbnails/page. No unbounded image queue: one source proxy/face request at a time, shared decoder synchronization, two intra-op helper CPU threads, 60-second face-helper deadline. The lightweight overview includes derived `blurry` / `closed_eyes` issue flags and explicit issue-provider availability; details load on selection. Job-wide SQLite/source validation and per-photo face-helper startup remain likely bottlenecks. Synthetic 500/1,000/3,000 grouping and first-hash versus cached-hash timings are recorded separately in [VERIFICATION.md](VERIFICATION.md); no real 3,000-RAW throughput or RAM certification is claimed.

Tauri runs work off its event loop; the UI polls lightweight progress. The primary status reports only completed/total photographs; byte counts, cached identities, hashing time, identity failures and source-analysis failures are kept in collapsed development details. Cancellation propagates to nested analysis/helper work and checks hash chunks, measurements, rows and groups. Codec/OS I/O retain noninterruptible sections. Completed hash cache rows and per-asset absolute assessments commit immediately; final exact/visual ratings swap atomically. Incomplete grouping never claims Unique. Cancellation preserves completed photos, overrides and editing selection. Queued permit release/startup interruption are recoverable; explicit resume reuses finished work. Concurrent membership changes require resume after scanning; membership/generation validation prevents old results from being shown as current.

## Grid and editing selection

Open a job → AI Culling → choose photo type → Run. The primary workflow is Filter photographs → optionally refine the automatic selection → Run for Editing. Rating controls are All / 5★ / 4★+ / 3★+ and always use the **effective** rating. Duplicates Show/Hide, Hide Blurry, the unavailable-aware Hide Closed Eyes control and Show All are first-class controls. Every membership-changing filter action atomically replaces the editing selection with all matching asset IDs across every page. Show All resets rating to All, shows duplicates, disables issue hiding and selects every resulting photograph; it never changes ratings, AI evidence or overrides.

Duplicates Hide removes redundant exact copies and Near Duplicate/Burst alternatives from the filtered set, keeping the exact canonical and one deterministic display representative for each visual group even when several frames remain technical ties in the immutable assessment. Because filter changes define editing scope, the remaining representatives become the selected set. Similar Composition alone is never hidden, and unique/unclassified photographs remain visible. Show restores and selects every alternative still matching the other filters. Compact cards contain thumbnail/filename, effective stars, selection and only simple `BEST`, `DUPLICATE`, `SIMILAR`, `BLURRY` or `CLOSED EYES` labels. AI-versus-user ratings, review counts, relationship taxonomy, exact/group counts, arbitrary-star/relationship/selected-only filters, sort, confidence, provenance and source/hash diagnostics live in the inspector/development details. Manual rating override is in the selected-photo inspector; safe focused-thumbnail 1–5 shortcuts remain.

Selection remains an explicit persisted asset-ID snapshot, but the primary Select Shown step is gone. Changing rating, duplicate visibility or either available issue filter derives the exact matching IDs and replaces the snapshot automatically. React updates the count and every visible checkbox first, then serializes full-snapshot persistence in the background; Run for Editing stays disabled until that write finishes. A checkbox can include or exclude an individual photograph for the current filter state. The next filter change intentionally discards those manual checkbox refinements and derives a new snapshot. Clear Selection saves an empty set without changing the visible filters and nothing is reselected until another filter change. The UI prominently reports `N selected` and `Showing N of total`. Run for Editing is disabled for an empty or syncing selection and otherwise opens the [preset editing workflow](PRESET_EDITING.md) with only the persisted IDs; there is no fallback to job assets, visible assets or an older selection.

`BLURRY` is currently derived only from the existing high-confidence `severe_subject_softness` gate; mild softness and generic low texture are not promoted to a categorical issue. `CLOSED EYES` is derived only from a reliable `eyes_closed` reason and preserves per-person indices in the detailed evidence. The shipping eye provider identifies itself as unavailable, so its primary control is disabled and explicitly says Unavailable rather than implying all eyes are open. If a real provider is installed, Hide Closed Eyes defaults on.

The inspector includes development-oriented focus diagnostics: global/subject/face measurements and confidences, internal absolute/final scores, visual-group median face detail, selected-to-median ratio/outlier status, interpreted focus severity and any severe-defect rating cap. These are explainable heuristics, not calibrated probabilities. The recursive sample folder contains 53 assets representing 52 distinct photographs because one blurry CR3 is intentionally duplicated. Its production result is 10×5★, 37×4★ and 6×1★: five distinct severe frames plus the redundant exact copy. Its absent 2★/3★ bands reflect this set's evidence, not a quota or an unreachable band; realistic structured combinations still produce all five ratings.

## Evidence and boundaries

See [VERIFICATION.md](VERIFICATION.md) for exact commands/counts, measured timings and the 53-asset/52-distinct-photo calibration result. Structured open-eye/blink/group fixtures test policy, not real eye detection. The local acceptance job exercised actual portrait CR3/JPG measurements and was re-culled without modifying source photographs; it is one calibration set, not broad accuracy certification. Real-estate/landscape quality, native interactive acceptance and macOS remain unverified.

Defer calibrated eye state, full-resolution face detail, anatomical head/body cutoff, semantic camera-shake/focus/flash/reflection models, learned aesthetic judgment, cross-job/global perceptual indexing and commercial quality certification. Exact full-file buckets are job-wide; visual comparisons remain bounded heuristics. Also out of scope: trained presets, learned feedback, scene-consistency processing, PhotographerApp integration, cloud services and distribution/signing. The current preset screen applies only the three deterministic built-ins documented in [PRESET_EDITING.md](PRESET_EDITING.md).
